3. Deep Root Cause Analysis

Cause 1: Exclusion of Credit Notes in Next.js Code

In Frappe, when a student drops out, changes courses, or receives a refund, Frappe creates a Return Sales Invoice with is_return = 1. This posts a debit to the Sales GL account to reduce revenue.

In src/app/api/director/report-summary/route.ts (line 216), the Next.js query explicitly filtered out return invoices:

// CURRENT CODE: Excludes returns and sums only positive invoices const branchInvoices = invoices.filter( (inv) => inv.company === branch && !inv.is_return && (Number(inv.grand_total) || 0) > 0 ); const totalFee = branchInvoices.reduce((sum, inv) => sum + (Number(inv.grand_total) || 0), 0);

As a result, the Next.js portal displayed the Gross Fee Invoiced rather than the Net Revenue.

Cause 2: Frappe Consolidated Financial Statement Includes "Indirect Income"

Frappe’s Consolidated Financial Statement displays Total Income: ₹2,98,56,642.74. In Frappe ERPNext, Total Income consists of:

  • Direct Income (Sales - SU): ₹2,98,50,277.00 (Fee revenue generated from student tuition fees net of returns).
  • Indirect Income (Indirect Income - SU): ₹6,365.74 (GL rounding differences, bank interest, and exchange gains — e.g. Kadavanthara has ₹6,093.98 in indirect income).

The Next.js Director Reports only tracks student tuition fees, which correctly maps to Direct Sales Income.

Cause 3: Filter Semantics ("Admission Date" vs "Posting Date")

In the Director Reports UI, the filter is labeled ADMISSION DATE. However:

  • The student count (1,640 students) is filtered by Student.joining_date.
  • The invoice totals are filtered by Sales Invoice.posting_date.
  • Frappe’s Consolidated Financial Statement has no concept of student admission dates; it strictly groups accounting vouchers by transaction posting date.

4. Recommended Architectural Structure & Fix

Fix 1: Deduct Returns in Next.js Server Route

Update src/app/api/director/report-summary/route.ts to calculate both Gross and Net Fee:

const branchInvoices = invoices.filter((inv) => inv.company === branch); // 1. Gross Invoiced Fee const grossFee = branchInvoices .filter((inv) => !inv.is_return && (Number(inv.grand_total) || 0) > 0) .reduce((sum, inv) => sum + (Number(inv.grand_total) || 0), 0); // 2. Deduct Credit Notes / Returns const returnFee = branchInvoices .filter((inv) => inv.is_return) .reduce((sum, inv) => sum + Math.abs(Number(inv.grand_total) || 0), 0); // 3. Net Total Fee (Matches Frappe Direct Sales) const totalFee = grossFee - returnFee; const pendingFee = branchInvoices.reduce((sum, inv) => sum + (Number(inv.outstanding_amount) || 0), 0); const collectedFee = totalFee - pendingFee;

Fix 2: Filter Toggle in Director UI

Provide an explicit date filter toggle in the header:

  • Accounting Date (Posting Date): When the Director wants to audit financial figures against Frappe ERPNext / CA audits.
  • Admission Date (Joining Date): When analyzing fees strictly belonging to the students enrolled in that specific intake cohort.
